Qué se construyó

Salón Lila es una app Expo (React Native) para un salón de belleza. Ana, clienta, reserva corte, coloración o manicure. Lila, profesional, abre el calendario y ve las citas del día. La misma interfaz corre en el teléfono y en el navegador. Maestro prueba la versión web: demuestra el extremo a extremo sin un simulador.

Cómo se conecta

El feature define el comportamiento. Cada escenario es un YAML. Maestro abre Chromium, toca la app y la app habla con la API. El PNG de cada flow alimenta el otro HTML.

Flujos de la app

Confirmar hace POST /api/bookings. Si el horario ya tiene cita, la API responde 409 y la app muestra el mensaje. La agenda de Lila lee las mismas filas, ordenadas por hora.

Librerías

  • Expo 57 y React Native 0.86, con React Native Web, para una sola UI en teléfono y navegador.
  • Hono sirve la API en el puerto 3001.
  • SQLite (node:sqlite) guarda personas, servicios, horarios y citas.
  • Zod valida el body y la query en el borde HTTP.
  • Effect expresa el caso de uso: reservar un hueco ocupado es SlotTakenError.
  • Maestro 2.11 ejecuta los YAML. En esta máquina la plataforma es Web / Chromium (--headless --screen-size 390x844).

Patrones

  • Gherkin manda. Cinco escenarios, cinco archivos en maestro/. Cómo se escriben y cómo se corren está en docs/QA-MAESTRO.md.
  • Reset determinista. Cada flow toca reset-data y espera “Datos listos”. Eso deja las 10:00 ocupadas (María, corte) y 11:00, 14:00 y 16:00 libres. El orden de los flows no importa.
  • Selectores estables. Maestro usa id (testID de React Native, que en web es data-testid), no coordenadas.
  • El error vive en el dominio. La UI no inventa “horario ocupado”: muestra el texto que devuelve la API.
  • Misma app, dos superficies. Los YAML apuntan a url: http://127.0.0.1:8081. En un simulador se cambia esa línea por appId: com.salonlila.app. Los ids siguen iguales.

La evidencia visual de cada escenario está en escenarios.html. Comandos de arranque: el README.
